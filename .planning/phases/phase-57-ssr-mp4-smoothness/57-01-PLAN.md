# Phase 57 — Plan 01: Symmetric mp4 frame-rate gating + asymmetric defect repair

**Status:** READY-TO-EXECUTE
**Date:** 2026-06-01
**Atomic:** Yes — single wave, all changes interdependent

---

## Goal

Eliminate the constant-low-FPS-feel stutter on snow.mp4 in the SSR-rendered `/output/` stream, by bringing all three SSR mp4 paths (inside, room, outside) up to the same defense level. Specifically: rate-gate canvas paints to match the mp4 source frame cadence so 30fps mp4 source isn't oversampled at 40-60Hz rAF (the universal stutter mechanism).

Operator-confirmed symptom: konstantes leichtes Stockeln; bug shows on snow.mp4 regardless of room/inside/outside spawn site (per 57-CONTEXT.md D-01, D-02).

## Change Surface

Three changes in two files. All in `src/app/runtime/render/`.

### Change 1 — `runtime-draw-loop.js` inside-mp4 path (lines 290-306)

**Current state (the asymmetric defect):**
```javascript
if (definition?.assetType === "mp4") {
  const videoEntry = ctx.getOutsideVideoElement(definition.assetRef);
  if (videoEntry?.video) {
    const video = videoEntry.video;
    const playbackRate = Math.max(0.15, Math.min(4, speed * state.animationSpeed));
    video.loop = true;  // ← native loop, no seam machinery
    if (Math.abs((Number(video.playbackRate) || 1) - playbackRate) > 0.01) {
      video.playbackRate = playbackRate;
    }
    if (video.paused) void video.play().catch(() => undefined);
    c.globalAlpha = intensity;
    c.drawImage(video, 0, 0, ctx.canvas.width, ctx.canvas.height);
    //  ↑ bare drawImage every rAF — no readyState check, no gating, no fallback
    return;
  }
}
```

**Target state (backport outside-mp4 non-final-output pattern):**
- Replace `video.loop = true` with `ensureOutsideMp4Playback` + `maybeWrapOutsideMp4Loop` (manual loop wrap, matches outside path)
- Add live-frame check (`!seeking && readyState >= 2 && videoWidth > 0 && videoHeight > 0`)
- Gate via `ctx.shouldDrawOutsideMp4Now(playbackState)`
- Capture fallback frame on live paint via `ctx.captureOutsideMp4FallbackFrame`
- Replay fallback when not live or gated via `ctx.drawOutsideMp4FallbackFrame`

Reference shape: outside-mp4 non-final-output branch in `runtime-draw-loop.js` lines 557-566.

Note: the inside-mp4 path uses `ctx.getOutsideVideoElement(definition.assetRef)` (line 291) — same video-element store as outside, so the outside playback machinery (ensureOutsideMp4Playback etc.) is the natural fit.

### Change 2 — `runtime-draw-loop.js` outside-mp4 final-output branch (lines 520-556)

**Current state (the "always paint, never gate" optimization from Phase 30 T4):**

Comment block at lines 504-519 explains: "on /output/ ... the rAF rate is below any tier-target gate, so shouldDrawOutsideMp4Now never returns false → the fallback canvas is dead weight. Always paint the live frame, never capture, never replay."

**This assumption is wrong on the operator's modern PC** where /output/'s rAF runs at 60Hz and the tier target is 33/22/16ms (= 30/45/60 fps). The gate DOES return false now, but the path bypasses it.

**Target state:** Drop the `isFinalOutput` special-case branch entirely. Always use the tier-gated path with capture + fallback (the current non-final-output branch at lines 557-566). This matches /output/'s actual rendering rate to the mp4 source cadence.

Replace lines 520-566 with a single unified branch that always uses tier-gating + capture + fallback.

### Change 3 — `runtime-draw-loop.js` room-mp4 path (lines 83-136)

**Current state:** has live-frame check ✓, has fallback capture ✓ — but paints every rAF (no rate gate). Same oversampling problem as outside-final-output had.

**Target state:** Add `ctx.shouldDrawOutsideMp4Now(playbackState)` gate around the live-paint branch. If gated out, replay the fallback via `ctx.getRoomMp4FallbackSource(playbackState)` (already present in else branch). The room playbackState shape includes `lastDrawAtMs` (set by `ensureRoomMp4Playback` — verify by reading runtime-outside-mp4.js room helpers).

If `shouldDrawOutsideMp4Now` was designed only for outside playbackState shape, add a `shouldDrawMp4Now(playbackState)` shared helper that works on either shape — both have `lastDrawAtMs`.
